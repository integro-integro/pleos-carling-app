# 카링 기능별 개발 가능성 리포트

- 작성일: 2026-10-31
- 기준 문서: `CARLING_기획안_v0.2.md`, `CARLING 서비스 시각화.pdf`
- 검증 환경: Pleos Connect Emulator v2.1.0 (Android 14), Vehicle SDK 2.3.2, NaviHelper SDK 3.0.5
- 검증 방법: Pleos Playground 공식 문서 확인, SDK 바이너리(AAR) API 시그니처 직접 확인, 에뮬레이터에 앱을 설치해 동작 확인

## 요약

| 구분 | 개수 | 내용 |
|---|---|---|
| ✅ 가능 (검증 완료) | 12 | 부화·성격·이름, 주행/정차 UI 전환, 충전 반응, 주행 세션·도착 리포트, 함께한 날·성장 단계, 빛 판정, 수치 3종, 선물·추억 카드, 이유 설명 |
| 🟡 가능하나 제약 있음 | 3 | 길(단골/탐험) 판정 (내비 탑재 차량 한정), 부드러운 운전 칭찬 (기준값 실차 보정), 시동 시 자동 시작 (에뮬레이터 확인, 실차·심사 확인 필요) |
| 🔴 현재 불가 | 5 | Pleos ID 계정 연동, Gleo AI 대화, 동승자 감지, 주유 이벤트, 음성 한마디 (TTS 초기화 실패) |

**결론:** 기획안 8장의 MVP 범위는 대부분 구현할 수 있다. 다만 기획안 9장의 핵심 가치인 **"차를 바꿔도 이어지는 카링(Pleos ID 연동)"은 공개 API가 없어 구현할 수 없다.** 기획서에는 이 기능을 '확장 단계'로 옮겨 적는 것을 권장한다.

## 2. ✅ 개발 가능 (검증 완료)

| 기획 기능 | 사용 신호/API | 검증 결과 |
|---|---|---|
| 알 깨우기 → 성격 고르기 → 이름 짓기 | 앱 내부 | 에뮬레이터에서 동작 확인 |
| 주행 중에는 위젯, 정차 시 전체 화면 | Vehicle SDK `Gear.registerGearSelection` (권한 `CAR_DRIVE`) | P↔D 전환 확인. **`distractionOptimized` 선언이 없으면 주행 중 앱 화면 자체가 차단됨** |
| 충전 때 함께 밥 먹기 | `EvBattery.registerEvChargePortOpen`, `registerEvBatteryStateOfCharge` (권한 `CAR_ENERGY`) | 충전구 열림 반응 확인 |
| 한 번의 주행 인식 (시작/종료) | 기어 P→D→P 전환 + `Odometer.getCurrentDistanceDriven` | API 존재 확인. 공식 "시동 이벤트" API는 없어서 기어 전환으로 대신 판단 |
| 도착 리포트 (함께한 시간, 거리, 칭찬, 성장) | 위 주행 정보 | 구현 가능 |
| 함께한 날 → 성장 단계 (7일 / 30일) | 주행한 날짜 집계 | 구현 가능 |
| 빛 판정 (새벽/햇살/노을/별빛) | 주행 시작 시각 | 위치 정보 없이 가능 |
| 성장도·친밀도·포만감 | 앱 내부 | 구현 가능 |
| 하루 첫 만남 먹이, 충전 시 포만감 회복 | 앱 내부 + 충전 신호 | 구현 가능 |
| 첫 드라이브 선물(모자), 추억 카드 | 앱 내부 | 구현 가능 |
| 변화 이유 설명 ("노을을 12번 같이 봐서…") | 빛·길 통계 | 구현 가능 |
| 빛 4종 × 길 2종 = 8갈래 진화 외형 | 앱 내부 그림 | 임시 그림으로 가능. **정식 아트는 별도 제작 필요** |

## 3. 🟡 가능하나 제약 있음

### 3.1 길 판정 (단골 / 탐험)
- 기획: 처음 간 곳과 다시 찾은 곳의 비율로 판정한다.
- FusedLocation SDK는 Coming Soon이라 쓸 수 없다.
- **대안:** NaviHelper SDK의 `getCurrentLocationInfo()`(위도·경도·주소)와 `onDestinationArrived()`(목적지 이름)를 쓴다.
- **처리 방식:** 주행이 끝날 때 위치를 약 200m 격자로 뭉뚱그린 다음 해시값만 저장한다. 정밀 좌표는 저장하지 않는다(기획안 데이터 원칙 준수).
- **제약:**
  - 문서상 NaviHelper는 "내비게이션이 탑재된 차량에 한해" 동작한다.
  - 에뮬레이터에서 내비 경로가 없을 때도 위치가 오는지는 구현하면서 확인한다.
  - 위치가 오지 않으면 길 판정은 기본값(단골)으로 처리한다.

### 3.2 부드러운 운전 칭찬
- Vehicle SDK에는 속도 값이 없다.
- **대안:** AAOS 표준 API인 `CarPropertyManager`의 `PERF_VEHICLE_SPEED`를 쓴다. 에뮬레이터에 이 값이 등록되어 있음을 확인했다.
- **제약:**
  - `android.car.permission.CAR_SPEED`는 사용자 동의가 필요한 런타임 권한이다.
  - 앱 마켓 심사 때 사용 목적을 설명해야 할 수 있다.
  - 급가속/급감속 기준값은 실제 차량에서 다시 맞춰야 한다.

### 3.3 음성 한마디 (3초 이내) — 검증 결과 현재 불가
- Pleos TTS SDK는 Coming Soon이다.
- **시도한 대안:** Android 표준 `TextToSpeech` API. 에뮬레이터에는 Pleos 음성 서비스(`ai.pleos.playground.caas`)가 TTS 엔진으로 등록되어 있다.
- **결과:** 초기화가 `-1(ERROR)`로 실패했다. 기본 엔진과 엔진을 직접 지정한 경우 모두 실패. Pleos 클라이언트 ID 등록이 필요한 것으로 보인다.
- **조치:** 코드는 남겨두고 실패하면 무음으로 동작한다. Pleos TTS SDK가 공개되면 교체한다. 오디오 포커스 정책(내비 안내 음성과 겹치는 문제)도 그때 함께 검토한다.

### 3.4 앱을 닫아도 주행 기록
- 성장 데이터는 매 주행을 놓치지 않아야 정확하다.
- 확인된 것: 공식 문서상 Pleos는 화면에서 사라진 앱을 종료하지 않고 백그라운드에 유지한다. 백그라운드 작업은 최소화하라고 권고한다.
- **구현:** 차량 신호 수신을 앱 전체 범위에 두고, 다음 두 가지로 앱을 살려 둔다.
  - 부팅 완료(`BOOT_COMPLETED`)를 받으면 앱을 깨운다.
  - 아무 일도 하지 않는 포그라운드 서비스(`specialUse`)로 프로세스를 유지한다.
- **에뮬레이터 검증 (2026-10-31):**
  - 재부팅 후 약 30초 만에 앱이 자동으로 시작됐다. 포그라운드 서비스도 허용됐다.
  - **카링 화면을 한 번도 열지 않은 상태에서** D→P 주행이 기록됐다. 나중에 앱을 열면 도착 리포트가 기다리고 있다.
  - 주행 도중 프로세스가 종료돼도, 다시 뜨면 저장된 시작 시각으로 이어서 기록한다.
- **남은 확인 (실차·심사):**
  - 실제 차량은 시동을 끌 때 완전히 꺼지지 않고 절전(suspend) 상태로 들어갈 수 있다. 이 경우 부팅 신호는 오지 않지만, 포그라운드 서비스가 프로세스를 유지하므로 그대로 동작할 것으로 예상한다. 실차에서는 확인하지 못했다.
  - 상주 서비스가 Pleos 앱 심사의 "백그라운드 상주 최소화" 권고와 충돌하는지는 문의가 필요하다 (partnership@pleos.ai).

## 4. 🔴 현재 불가

| 기획 기능 | 불가 사유 | 대안 |
|---|---|---|
| Pleos ID 연동 (차를 바꿔도 같은 카링, 가족 운전자별 분리) | 계정/프로필 API가 공개되어 있지 않음. 에뮬레이터에 `ai.pleos.service.profile` 패키지는 있으나 3rd party용 SDK가 없음 | MVP는 기기 안에 저장. 기획서에는 '확장 단계'로 표기 |
| Gleo AI 음성 대화 | Gleo Interface 문서가 "개발 진행 중" 상태 | 확장 단계로 미룸 |
| 동승자 축 (혼자·연인·가족) | Vehicle SDK `Seat`는 좌석 위치·열선 위주이고 탑승 감지 API는 확인되지 않음 | 기획안대로 확장 후보 유지 |
| 주유 이벤트 | `Fuel` 도메인은 연비 정보만 있고 주유 이벤트가 없음 | EV 충전만 지원. 내연기관차는 연료량 변화로 추정하는 방식을 검토 |

## 5. 기획서 반영 권장 사항

1. **8장 "[보강 필요] 신호별 API명"**은 이 문서 2·3장의 표로 채운다.
2. **"차를 바꿔도 이어지는 카링"**은 MVP가 아니라 확장 단계로 옮긴다. 9장의 기대효과 문구도 함께 고친다.
3. **안전 원칙**에 "주행 중에는 Distraction Optimized 위젯만 노출한다"를 명시한다. 심사 기준인 차량특화성과 앱 심사 대응 양쪽에 유리하다.
4. **음성은** 에뮬레이터에서 표준 TTS도 동작하지 않았다. "Pleos TTS SDK 공개 후 적용(확장 단계)"로 적고, MVP는 말풍선 텍스트로 대체한다.
5. **위치 활용은** "NaviHelper 기반, 격자 해시만 저장"으로 구체화한다. 개인정보 원칙과도 맞는다.

## 6. 개발 진행 순서

1. 주행 세션 기록 (앱 전체 범위)
2. 도착 리포트, 함께한 날, 성장 단계
3. 빛 판정, 친밀도·포만감, 충전 판정 개선
4. 첫 선물, 추억 카드, 변화 이유 대사, 개발용 시간 건너뛰기
5. 길 판정 (NaviHelper), 부드러운 운전 칭찬 (차속), 음성 한마디 (TTS)

진행 결과는 이 문서 하단 "구현 현황"에 갱신한다.

## 구현 현황 (2026-10-31, v0.3.0 · 에뮬레이터 검증)

**MVP 중 현재 SDK로 개발 가능한 기능은 모두 구현했다.** 남은 항목은 SDK·Pleos 정책 때문에 막혀 있거나(🔴), Pleos 측 확인이 필요한 것(🟡)뿐이다.

### 추가로 확인한 것
- **release 코드 축소(R8)를 켜면 실행 즉시 종료된다** (Kotlin 표준 라이브러리 `IllegalAccessError`). 그래서 release에서도 축소를 끄고 배포한다.
- **서명 키**(`keystore/carling-release.jks`, `keystore.properties`)는 저장소에 넣지 않는다. 키를 잃어버리면 같은 앱으로 업데이트할 수 없으니 반드시 따로 백업해야 한다.
- 장소 이름은 내비가 주는 동 단위 주소를 리포트와 추억 카드에만 쓴다. 판정용으로는 격자 해시만 저장한다.
